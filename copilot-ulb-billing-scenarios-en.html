Key Concepts

AI Credits
Billing unit
1 credit = $0.01 USD
Pool (Shared Pool)
All seat included credits merge into one shared pool — not individual buckets. Adding a license grows the pool immediately; removing one shrinks it on the next billing cycle.
ULB
User-Level Budget — tracks each user's total spend (pool + overage). Stops usage when reached. $0 = user cannot use Copilot at all.
Org Budget
Sets the maximum additional usage (overage) spend allowed at the organization level.
Enterprise Budget
Controls the overage spending cap across the entire enterprise — a global kill switch across all orgs.
"Stop usage" Checkbox
"Stop usage when budget limit is reached" on the Budget page. Must be checked for a hard stop; unchecked means alert-only. Budget = $0 + checked = no overage allowed.

  • Each org has 25 users × ULB $40 → per-user max $40; per-org overage capped at Org Budget $500 (less than ULB×seats $1,000).
  • Overage spend is counted simultaneously against both the Org Budget and the Enterprise Budget.
  • Org A hits $500 → Org A is blocked; Org B is unaffected.
  • Enterprise Budget hits $800 → all orgs are blocked immediately, even if Org B hasn't spent its own $500 yet (this is the "global kill switch" effect).
  • Monthly estimate: seats + up to $800 overage (Enterprise Budget only acts as a real brake when it's less than the sum of all Org Budgets).
Key risk: If Enterprise Budget ≥ sum of all Org Budgets, it's decorative. If < the sum, heavy spending by Org A squeezes Org B's available headroom.

Management Best Practices

1

Always check "Stop usage when budget limit is reached"

When configuring a budget, you must check this option to enforce a hard stop.

If left unchecked, the budget only triggers an alert — it will not stop usage. This can lead to unexpected charges and is the most common management oversight.
Setting up budgets Stopping usage
2

Use Budget amount to control whether overage is allowed

The new GitHub Billing UI does not have a standalone "Additional usage allowed / not allowed" toggle — that control is now integrated into the Budget settings. The actual behavior is determined by the budget amount combined with the "Stop usage when budget limit is reached" checkbox:

  • Budget = $0 + Stop usage checked: Equivalent to "Not allowed" — stops entirely when Pool is exhausted.
  • Budget > $0 + Stop usage checked: Equivalent to "Allowed up to budget" — continues after Pool is depleted at published rates, then hard stops at the budget limit.
  • Stop usage unchecked: Unlimited overage after Pool is gone; budget sends email alerts only. Not recommended.
  • No budget set: Follows plan defaults (Business/Enterprise default to no overage; individual Pro accounts follow GitHub plan terms).
Set up budgets Exceed included credits
3

Enable Included Usage Alerts

On the Budgets & Alerts page, you can enable included usage alerts:

  • Receive email notifications when Pool reaches 90% and 100%.
  • This is a separate mechanism from budget alerts: one tracks included usage consumption percentage, the other tracks dollar spend.
  • Recommended: enable both.
